# mosaico-peek

- Retain the approved dragon plus appended night_owl/deep_sea/mechanical native views. The supplied eye pack is source/reference, not a browser runtime replacement. Hardware writes require explicit task authorization.
- `src/peek.c` is the single Host/ESP-IDF detector implementation. Rendering must never submit samples. The acquisition task runs `peek_live_event` on every successful **complete** frame or read fault, before the latest-only display mailbox. GSP owns an independent detector/role snapshot; never feed it back into acquisition. Display may skip transient states, so do not claim every fault is shown. Core event exits must already be aged and same-time tick idempotent.
- The approved single-eye assets are in `assets/dragon/`; retain provenance. Generated `dragon_assets.inc` belongs in build directories and is regenerated by `tools/bake_dragon.py` (Pillow10.4.0 for byte identity). GSP resource and app-embedded assets count separately and in total Flash.
- Ordinary asset builds must only validate retained sources/provenance and write the build directory. Source/provenance updates require the explicit `--update-assets` entry.
- IDLE follows the approved2026-10-21 extension: calm gaze for10s after each IDLE entry,450ms close, then remain shut; only an acquired production hot target starts150ms wake. Faults/duplicates/redraws cannot fabricate wake evidence. Report active open-eye performance separately from cheap sleeping frames.
- `dragon.c` is the shared behavior/pose. Expire previous stillness evidence before accepting a new capture, then normalize the new capture again at the same receive time. Speed and stationary evidence use fresh capture timestamps; `held` is not stationary. Drawing reads a prepared pose only. Replay resets source, detector, role and seed together.
- Prepared240 geometry may reuse only exact blink/squint/tension keys. Gaze/pupil remain dynamic; changing geometry uses scalar until an exact repeat. The mutable prepared cache is built only in prepare and stays read-only during draw; count it separately from the immutable fixed-pixel table.
- Renderer fixed-pixel storage must be counted separately from texture Flash and use explicit PSRAM on device, without internal fallback. Propagate allocation errors; step1 remains the pixel-equivalent480 reference. The user explicitly approved step2 (240 odd-center samples replicated2x2 into480 output) on2026-10-21; device/native startup now defaults to2. Further detail reduction needs visual acceptance.
- The physical board30:ed:a0:f4:52:a0 uses both target-to-gaze flips (user motion feedback2026-10-21). Configure the source-owned dragon mapping before capture; never flip the768-temperature array or native detector coordinates. Native GSP uses explicit `--flip-x --flip-y` to reproduce the mount; preserve mapping across replay reset.
- Host throughput reports must separate normal preview from screenshot/poll conditions, and distinguish draw callbacks, host commit sequences and browser-visible/device FPS. RAM budgets must account for final XIP/PSRAM configuration and map reservations; zero decoding is not zero PSRAM cost.
- Keep injected monotonic time, sequence identity and replay epoch semantics in `README.md`. Reset all three on replay/source restart. Synthetic and recorded data must remain labelled and traceable.
- Use the pinned dependencies in `dependencies.json`, the project lock and the official Hello World application/retained Vibe Mode contract. Do not upgrade or edit adjacent checkouts. `deps/`, build output and `.run/` are local only.
- Tests: `cmake -S . -B build-host && cmake --build build-host && ctest --test-dir build-host --output-on-failure`; `python3 tests/test_replay.py`; with preview running, `python3 tests/test_gsp.py`.
- Project status/handoff: `docs/HANDOFF.md`. GSP results and hardware validation must be reported separately.

- Three-theme integration: `docs/EYE_UI.md`. `assets/eye-pack/` retained non-evidence files are immutable/checksummed; supplied Canvas-only evidence remains in ignored review-inputs. `bake_eye_pack.py` writes build-local lossless RGBA streams only. New art always full480; dragon's240 approval does not extend to these themes.
- All eye views consume the existing source-owned dragon behavior/pose (gaze/blink); theme switches preserve detector/time/seed/mapping. Host debug controls stay outside artwork; product touch gestures are handled by the shared C pointer observer. New bitmap textures decode in prepare, never draw, to explicit PSRAM without internal fallback.
- Current build uses `build/sdkconfig.eye-switch` version1.0.4-peek-switch; retain the installed1.0.3-peek-eyes and prior1.0.2-peek-sleep restore bundles separately. Installed identity and authorization history belong in HANDOFF. `tools/package_review.py --eye-ui` includes new native movies and omits historical firmware/evidence binaries.
