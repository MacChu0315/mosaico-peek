# Idle sleep and exact240 geometry reuse

User acceptance requires both roughly doubling the preceding7.5Hz device engine
rate and enriching IDLE: look calmly for about10s, close, then wake quickly when
a hot target is acquired. Keep the approved artwork,2x2 detail, both physical
mount flips and detector parameters. Source implementation is shared C; neither
recorded focus nor device-specific animation logic substitutes for detection.

## Role

`dragon.c` keeps the public mode IDLE and adds sleeping/waking flags. After each
IDLE entry,10,000ms of calm authored gaze/blinks precede450ms of closing. The eye
stays fully closed until an active production result arrives; pending hot-region
candidates, read faults and stale data do not wake it. A confirmed target starts
150ms opening from the current closure, schedules the next normal blink and
uses the existing NOTICE/follow controller. LEAVE and reentry reset the idle
age. Monotonic injected time and seeded replay still apply; advance the old idle
deadline before a new acquisition, even if no draw tick happened during closing.
Completed normal-blink counters exclude hidden blinks during sleep/wake.

## Renderer

The preceding source spends about91ms raster plus31ms submit per engine frame.
The new cache has57,600 entries, one per approved240 sample center. It is built
only in prepare after blink/squint/tension exactly repeat. Gaze and pupil are
never keys; their current values always drive dynamic eye shading. No pose
quantization or new detail reduction. Changing geometry invalidates reuse and
uses the retained scalar shader until an exact repeat, avoiding rebuilding on
every intermediate blink/NOTICE frame. All draw surfaces share one prepared
generation; draw allocates/mutates nothing.

Each cached center is either:

- static: the eyeball has zero coverage, so final RGB565 is independent of gaze;
- interior: eye coverage256 and every lip/border/shadow contribution is exactly
  zero; evaluate current eyeball, original gloss and vignette directly;
- boundary: retain the complete scalar compositor.

The additional prepared cache is691,200B explicit PSRAM, separate from the
3,225,600B immutable fixed-pixel cache. Creation propagates the third allocation
failure and releases both earlier allocations; no internal-RAM fallback. Memory
reports compile the actual target structures and count both caches separately.
A full closed-eye frame is cheap, so its rate cannot establish follow smoothness.

## Evidence

Host Debug/Release15 CTests include new sleep/deadline/wake regressions,80 complete
sampled cached-vs-scalar frames, dynamic gaze/pupil changes, all three cache
classes, allocation failures and actual device telemetry classification. The43
retained original full480 reference frames are identical. ASan/UBSan cache run
passes (existing leak-check/ptrace limitation remains; explicit free counts run).
Native GSP has10 new actual sleep/wake checkpoints and a34s wall run,27 existing
role checkpoints, and29 actual PNGs checked at every RGB565 pixel against the
same scalar shader/approved2x2 rule. The first new screenshot test captured an
old committed frame after control ack; the helper now follows the existing
`wait(frames=2)` convention. Its failed observation is retained separately.

`data/sleep.peek` is labelled synthetic and reproducibly generated by
`tools/generate_dragon_data.py`; all positions come from production C detection.
The native movie samples real GSP screenshots, and its variable-rate encoding preserves original capture wall-time intervals and
is not a performance measurement. Complete511-array/655-event real replay retains the
original timeline, with no resampling. Hardware results are recorded in HANDOFF
only after actual installation and observation.

Read-only firmware RPC publishes sleeping/waking/cache status plus cumulative
active-open engine counters. Completed GSP generations are classified using the
**previous** prepared pose: target_active, blink==0, not sleeping/waking. Includes
cache misses and excludes closed-eye frames. A Host fixture checks previous-vs-
next-pose transitions, exact elapsed/raster/submit sums,2048B response and query
purity. Rates remain engine rates, not measured physical panel-visible FPS.

## Stopped trial

Installed f8845c5 reached10.336 active-open engine frames/s, short of about15Hz.
The user chose to keep it and stop further optimization/installs. Physical trial
showed TRACKING/HOLD, not sleep/wake; native sleep/wake passes are separate.
WIPa6a0fb1 on wip/dragon-packed-color is uninstalled and not current mainline.
It explores color return layout and raster-only-O3; Host15/15 is not a hardware
validation or speedup. Reporter typo was corrected after installed source commit;
final target ABI counts renderer3,929,120B including691,200B prepared cache.
