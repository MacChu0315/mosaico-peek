# C 的动作约定

## 1. 状态归属与输入语义

本 UI 只消费主工程已经提供的目标确认结果、位置有效性、角色状态及时间信息。它不读取传感器、不从温度图计算目标，也不把预先编排的移动当作真实跟踪。

必须区分以下情况：

| 输入情况 | 可产生的视觉行为 |
| --- | --- |
| 有效数据，已确认目标 | 按主工程角色状态进入 NOTICE、TRACKING、HOLD 或 waking |
| 有效数据，仅有待确认候选 | 不触发 NOTICE，不唤醒，不按候选坐标追踪 |
| 有效数据，无明确目标 | 按主工程状态运行 LEAVE、IDLE 或 sleeping |
| 数据无效 / 中断 / 过期 | 保持最后有效姿态，等待主工程给出恢复或退化状态；不能直接等同“目标离开” |

`sleeping`、`waking` 是视觉行为状态，不能增加到检测结果类别中。状态权威来自共享角色逻辑。以下 `closure` 是文档中的视觉参数名称，不是声称已经存在的 C 接口：0 为快门最大开放，1 为完全闭合。

## 2. 正常状态

本节描述动作形态。进入阈值、持续时长、截止时间、插值相位和循环节奏全部服从主工程最新规则。**本包不新增工程定时常量。** 若 main thread 希望改变原角色行为，应将改变作为单独建议审阅。

| 视觉状态 | 进入前提 | 画面与动作 | 循环、打断和恢复 |
| --- | --- | --- | --- |
| IDLE | 主工程处于无确认目标的默认状态 | 眼球回到主工程给定的默认姿态，快门开放。可保留共享角色逻辑原有的轻微待机动作 | 使用主工程既有循环；有效候选不打断。确认新目标、进入休眠或切出时终止当前循环 |
| NOTICE | 主工程报告“首次确认目标”事件或对应角色状态 | 在当前姿态上作轻微快门收拢并恢复开放，眼球开始朝确认目标方向转动 | 一次性。新位置继续参与跟随；中途切出取消。恢复显示时不凭“有目标”重复制造首次确认 |
| TRACKING | 确认目标持续有效，主工程给出跟踪状态 | 眼球与中央快门整体跟随目标姿态；固定镜座不动。正常开放度由角色输出决定 | 连续跟随，无本地固定焦点时间线；状态改变时从当前实际姿态继续 |
| HOLD | 主工程确认目标持续静止并进入 HOLD | 保持主工程输出的注视方向；可用轻度快门收拢表达专注 | 静止判定、持续时间由主工程处理，素材层不重新计算。目标再次移动即按新角色状态恢复跟随 |
| LEAVE | 主工程确认目标离开并进入 LEAVE | 从离开瞬间的姿态自然回到默认位置，快门恢复默认开放度 | 一次性，按主工程截止时序收尾。新的确认目标可立即打断回正，从当前值转向目标 |
| sleeping | 主工程待机计时满足既有休眠规则 | 中央快门完全闭合；圆形镜座和琥珀色外圈仍可见。闭合表达休眠，不把整个画面熄灭当作眼皮 | 保持闭合，无自主追踪。候选、无效数据或切换页面本身不唤醒 |
| waking | 主工程在休眠期间确认新热目标并给出唤醒状态 | 从当前闭合程度快速恢复开放，同时朝主工程提供的目标姿态转动 | 按共享时序恢复，完成后服从 TRACKING / HOLD 等新状态。发生再次切出则取消本 UI 的临时任务 |

### 可选视觉建议（尚未写入主工程）

NOTICE 和 HOLD 的轻微收拢可作为 C 的角色特征，但不能改变确认逻辑或状态期限。若共享角色输出当前只有既有 `blink`，main thread 可评估将它映射为中央快门闭合程度；**这种映射尚未接入，也不意味着现有 `blink` 数值一定具备所需语义。** 初版也可以只保留主工程已有开合动作，不增加任何额外收拢。

## 3. 连续参数与图层运动

位置变化只影响共享角色逻辑给定的 `gaze_x`、`gaze_y` 姿态及其时间平滑结果；本 UI 不从这些数值反推目标种类、距离或身份。保留输入包的几何快照：球心 `(240,245)`，半径 `233px`，`gaze_x ∈ [-0.78,0.78]`，`gaze_y ∈ [-0.58,0.58]`，纯轴光学中心最大位移横向 `±120px`、纵向 `±80px`。对角姿态存在球面耦合。

快门开放程度与姿态是独立视觉参数。合成顺序为：在眼球贴图坐标内将中央快门合成到眼球底图 → 整体作球面投影 → 叠加固定镜座。不能将中央快门作为屏幕中心不动的覆盖物，否则视线移动时它会与琥珀色镜片脱离。

九帧精灵的默认映射为 `index = round(clamp(closure,0,1) × 8)`：00 全开，08 全闭。推荐离散切帧，**默认不混合相邻帧**，以免同时出现两套叶片边缘。非负数的中点取整采用 `floor(x+0.5)`，避免不同语言默认 `round` 行为差异。更平滑的策略需要 main thread 单独评估实际视觉效果和 GSP 能力。

每帧 240×240，放在眼球贴图 `(120,125)`；本地中心 `(120,120)`，半径 110px 外及开孔区域透明。透明开孔露出底图原有黑孔。九帧来自六叶片对应点的二维形变，闭态将原 AI 中央小六边形补片收束为六叶交点；它是固定美术帧，不是刚体机构或真实光圈物理仿真。SVG 保存单姿态的六叶片编辑参考，完整帧生成以 JSON 参数和构建脚本为准。

本 UI 不叠加另一套追踪缓动器。若主工程只提供原始位置、尚未提供角色姿态，平滑与角度约束需要在共享 C 角色逻辑中统一决定。不能用本地帧序号作为真实经过时间；动作发生中断时以注入的时间和当前插值相位续接。

## 4. UI 进入、切出与再次进入

| 进入时的主工程快照 | 首帧要求 |
| --- | --- |
| 已确认目标，正常互动状态 | 直接采用当前目标姿态和开合程度；没有新确认事件时，不重复 NOTICE |
| 有效无目标，处于 IDLE / LEAVE | 采用当前默认或回正过程姿态；不从某个任意演示位置开始 |
| sleeping | 首帧即闭合；页面切换不自动唤醒 |
| waking 进行中 | 使用当前实际相位继续，不重新播放完整唤醒 |
| 数据无效 | 不使用未验证坐标。使用共享角色逻辑保留的有效姿态或其明确指定的退化姿态 |

切出时停止本 UI 的绘制回调、局部插值任务、帧预取和资源访问；清除属于本 UI 的回调注册及过期引用。已经进行中的闭合、NOTICE、回正、唤醒不用为了“播完”继续占用显示。目标检测与全局角色状态由主工程管理，本 UI 不关闭共享检测器。

再次进入读取新的权威快照，不重放离开期间漏掉的动画，不恢复带旧时间基准的本地定时器。进入过渡若需要渐显，应由主工程统一的 UI 切换流程负责。

## 5. 输入与全局切换

C 没有需要按住、单击或滑动才能发生的角色动作，也不注册私有切换规则。用户交互由 main thread 统一处理。建议默认规则为左滑下一套、右滑上一套、单击下一套、AI 按键短按下一套；同一次滑动不能在松手后再触发单击。

AI 按键必须使用主工程实际 BSP 公共事件接口，并核实短按 / 长按行为，不能凭名称推定接口存在。将来若 C 增加点击互动，需要另行决定保留哪个全局切换入口；本包没有作该改变。

## 6. 模拟证据的解释

`preview/timeline.json` 定义 28 秒固定时间线，`evidence/input-timeline.csv` 保留逐帧输入，仅用于重复展示无目标、确认进入、左右 / 上下移动、HOLD、LEAVE、休眠、唤醒、动作中切出再进入，以及无效数据与恢复。时间线中的确认标志、角色状态和坐标均为人工注入。它们不证明传感器、候选确认、静止判断或检测算法有效。

预览所用时长只属于这条演示时间线，不能作为主工程休眠、唤醒、确认或丢失超时的新默认值。实际运行截图和 C/GSP 验证如未提供，应明确标为未完成。
