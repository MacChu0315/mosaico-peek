# C 素材接入说明

## 工程依据与本包边界

用户给定的 `eye-surface-art-handoff-v1.zip` 只提供本次沿用的尺寸与投影几何快照。本轮未取得主工程最新 `AGENTS.md`、`README`、`docs/HANDOFF.md`，因此本包不能宣称已适配当前 C 类型、构建器或 GSP 接口。main thread 应先核对最新工程规则，再把本包接入已有共享 C 角色实现。

本包只增加 C 的素材与参考说明。现有恶龙眼及其他 UI 保留；检测模块共享，不读取传感器，不修改全局手势、BSP、设备配置、依赖或固件。

## 1. 需要的输入（语义约定，不是新 C API）

| 字段语义 | 用途 | 约束 |
| --- | --- | --- |
| 数据是否有效、样本是否过期 | 决定是否可采用位置 | 无效不等于无目标；优先由主工程先完成时效判断 |
| 无目标 / 待确认候选 / 已确认目标的区分 | 控制视觉是否响应 | 仅确认目标触发首次注意或唤醒；候选不能冒充已确认 |
| 当前角色状态 | 选择 IDLE、NOTICE、TRACKING、HOLD、LEAVE、sleeping、waking 表现 | 状态归属共享 C，UI 不复制状态判定 |
| 当前姿态 / 有效目标位置及坐标约定 | 控制眼球朝向 | 实际位置格式、归一化方式、镜像和旋转由 main thread 明确 |
| 开合程度或可映射的动作相位 | 选择中央快门帧 | 不假定已有专用快门字段；若使用既有 blink，先核实其方向和语义 |
| 单调时间、动作起点 / 截止或等价相位 | 连续插值与中断恢复 | 实际注入接口由 main thread 提供，不能使用预览墙钟冒充工程时间 |
| UI 激活 / 退出与当前状态快照 | 初始化、释放、切回续接 | 进入时读取新快照，不重复生成检测事件 |

既有 C 接口若已能表达这些语义，应直接复用；不能为了本素材包另建一套检测协议或全局切换入口。

## 2. 原生合成方案

设计画布 `480×480`，左上原点，x 向右，y 向下。沿用几何快照：球心 `(240,245)`，半径 `233px`。纯轴中心位移上限横 `±120px`、纵 `±80px`；`gaze_x ±0.78`、`gaze_y ±0.58` 的球面耦合关系不改。

建议流水线：

1. 读取完整不透明的 `assets/processed/eye_surface.png`，尺寸 480×480，原点 `(0,0)`。
2. 计算 `index = floor(clamp(closure,0,1) × 8 + 0.5)`，把对应 `shutter_00..08.png` 放在眼球贴图原点 `(120,125)`。每帧 240×240，本地中心 `(120,120)`；半径 110px 外及开孔透明，露出底图原黑孔。默认离散切帧，不混合相邻帧。
3. 对合成后的眼球表面应用主工程已有球面逆变换与采样。
4. 在输出坐标 `(0,0)` 叠加 480×480 固定圆形 `frame.png`。相对球心半径不超过 221px 的内部透明，221–232px 为窄环，外围是不透明黑底。
5. 按主工程显示管线完成格式转换、裁切和呈现。

中央快门不是旧版上下眼睑。它必须与琥珀色镜片一起转动，不能放到第 4 步当作固定屏幕层。固定镜座不得烘焙进旋转眼球。C 不加载旧机械眼 `lid_00..08.png`，也不覆盖恶龙眼同名资源。

若 GSP 不能在球面采样中组合局部精灵，可由共享 C 先更新眼球纹理中的快门局部矩形，再调用既有投影；另一条备选是预合成有限数量的全幅眼球纹理，以更多资源占用换取较简单的采样路径。选择前需实测，不能从参考浏览器的流畅度推断设备表现。

本设计不需要 CSS 滤镜、WebGL、浏览器着色器或第三方运行时。球面投影、PNG 解码或构建时资源转换、预乘 alpha、局部纹理更新须按实际 GSP 能力核实。默认离散九帧不要求相邻帧混合；将来若评估混合，应在眼球贴图局部矩形中进行，并检查双叶片边缘。

快门帧采用六叶片对应点二维形变；SVG 只是单姿态六叶片编辑参考，不提供经过验证的物理光圈机构。原 C 开态经注册后的中央半径 184px、106,353 个底图像素保留，184–196px 为接合区域，196px 外是 AI 补充的连续金属采样面。该边界不等于旧 `locked_mask.png`。极限斜向下，正视投影纹理仍可能拉伸；需要在主工程原生采样路径中复查。

## 3. 资源生命周期

- **构建阶段**：按主工程格式将 PNG 转换成实际资源。生成产物与原始美术源分开，不将 PSD、预览代码或概念板编入固件。
- **进入 UI**：取得共享角色快照；准备眼球底图、固定镜座及所需快门帧。首帧选择服从 `MOTION_SPEC.md`，休眠进入即闭合。
- **运行阶段**：仅在开合程度改变时更新快门局部矩形；目标变化更新球面姿态。具体缓存策略由 main thread 根据资源预算决定。
- **切出 UI**：停止该 UI 的绘制回调、过渡任务和预取；解除回调引用后释放私有缓冲。共享检测器与全局角色状态继续由主工程持有。
- **再次进入**：重新读取权威快照和时间，避免旧回调访问已释放资源，也不追播已错过的动画。

本包不要求后台常驻一套独立时钟或任务。缓存保留与释放可统一交给主工程的 UI 管理器。

## 4. 资源开销估算（不是实测）

以下只按未压缩像素数计算；实际 PNG、固件压缩包大小以最终清单为准，解码器暂存、堆对齐、DMA、PSRAM 带宽和显示缓冲不在公式内。这也不是 Python / HTML 预览进程的内存占用：参考实现可能预合成全幅纹理并使用浮点数组，不能将其缓存策略原样当作嵌入式预算。

| 项目 | RGBA8888 理论字节数 |
| --- | ---: |
| 单张 480×480 眼球 | `480 × 480 × 4 = 921,600` |
| 单张全幅固定镜座 | `480 × 480 × 4 = 921,600` |
| 单张 240×240 局部快门 | `240 × 240 × 4 = 230,400` |
| 九张局部快门 | `9 × 230,400 = 2,073,600` |
| 全部素材常驻：底图 + 镜座 + 九帧 | **`3,916,800`，约 `3.735 MiB`** |
| 仅一帧快门常驻：底图 + 镜座 + 一帧 | **`2,073,600`，约 `1.978 MiB`** |
| 额外一张全幅合成工作缓冲 | `921,600`，约 `0.879 MiB` |
| 全部素材常驻 + 一张工作缓冲 | `4,838,400`，约 `4.614 MiB` |
| 一帧快门常驻 + 一张工作缓冲 | `2,995,200`，约 `2.856 MiB` |
| 九张全幅预合成眼球备选（仅眼球帧） | `9 × 480 × 480 × 4 = 8,294,400` |

`1 MiB = 1,048,576` 字节。上述“一帧常驻”只描述驻留像素量：换帧解码、临时重叠缓冲或预取仍可能增加峰值；不能将它直接视为设备内存上限。固定镜座大量透明也不会自动减小未压缩矩形容量，除非主工程另有裁块 / 压缩策略。全幅工作缓冲可否原地复用取决于实际采样生命周期，不能预先假定零额外缓冲。

每张 480×480 RGB565 图像理论为 `460,800` 字节，但透明层需要单独 alpha 或其他受支持格式，不能直接把所有层容量除以二。单次全幅采样至少涉及 `230,400` 个输出位置；实际耗时取决于取样、混合、缓存和呈现路径，本包不声称某个 FPS 或 CPU 占用。

## 5. 接入前必须由 main thread 决定或验证

1. 最新共享角色状态、输入数据有效性、确认事件和时间注入的实际 C 接口。
2. 既有动作参数是否可映射为快门闭合程度；NOTICE / HOLD 的附加轻微收拢是否采用。任何时序改变独立审阅。
3. 固定镜座与眼球的最终边界、锚点及极端四向 / 对角下的无遮挡采样质量；不能靠缩小既定摆幅掩盖缺陷。
4. GSP 的像素格式、alpha 约定、球面投影、纹理更新、裁切和精灵过渡能力；Host / 设备须走同一份共享 C 逻辑。
5. 九帧局部更新与全幅预合成两种路径的实际资源开销和设备性能。
6. 全局左 / 右滑、单击、AI 短按事件的接入。滑动松手抑制单击；AI 按键按实际 BSP 公共事件核实短 / 长按。
7. 资源切出、重入和异常数据恢复时的生命周期，以及实机长时间运行行为。

参考图、Python / HTML 预览及视频都不能代替上述原生或实机验证。当前没有真实 C/GSP 运行截图、设备录像或传感器检测证据。
