# 动作与状态规格

## 先区分状态规则和参考时序

本包使用主工程外部提供的角色状态来展示动作，不生成目标检测结果，也不定义主工程的目标确认、丢失、休眠或唤醒规则。状态名称来自本包参考契约；主工程的真实枚举、状态迁移和已有时序尚未提供。

文中的动作时长、追视平滑、眨眼和失效回退均为 **参考建议**。预览时间线是人为安排的模拟场景，不是传感器记录，也不能据此推断任何候选目标确认阈值或睡眠触发时间。

## 七种状态

| 外部状态 | 中文含义 | 画面行为 | 进入与退出的边界 |
|---|---|---|---|
| `IDLE` | 待机 | 以中性眼位为基础，可有克制的待机与眨眼 | 不自行把候选变成目标；休眠由外部状态决定 |
| `NOTICE` | 注意到确认目标 | 展示简短的注意动作，随后衔接当前目标方向 | 必须有外部确认语义；重入时不能补播已经过期的注意动作 |
| `TRACKING` | 跟随 | 平滑追随有效且已确认的目标坐标 | 不从候选坐标取得新的追视方向 |
| `HOLD` | 保持 | 以较缓的平滑保持对有效确认目标的安静关注，避免突然归中 | 按外部保持状态呈现；不替主工程延长或重置保持期限 |
| `LEAVE` | 目标离开 | 将关注动作逐步收回，回到中性方向 | 只消费外部离开状态；不能仅因一次坐标失效就推断离开 |
| `sleeping` | 休眠 | 眼睑闭合，保持安静 | 未确认候选不能唤醒；休眠期间不维持隐藏的追视动画 |
| `waking` | 唤醒 | 从闭眼过渡到睁眼，并衔接当前有效输入 | 唤醒由外部状态明确给出；不能因局部点击或候选擅自唤醒 |

这些是状态的视觉职责，不是本包新建的业务状态机。各状态是否可以相互迁移、由哪个模块迁移、何时迁移，均属于主工程。

## 输入有效性

有效追视样本必须同时满足：`data_valid === true`、`target_confirmed === true`、`target_x` 和 `target_y` 均为有限数值。正常输入应落在 `[-1, 1]`；本包对有限越界值裁剪并保留诊断标记，这只是参考防护，不替代上游数据校验。不得把 `0` 当作缺失值；`(0, 0)` 是有效的中心目标。

| 样本情况 | 可否更新追视目标 | 处理原则 |
|---|---|---|
| 数据有效，目标已确认，坐标合法 | 允许关注的状态中可以 | 在 `NOTICE`、`TRACKING`、`HOLD`、`waking` 中映射坐标并平滑处理 |
| 只有 `candidate_present` 为真 | 不可以 | 保留候选与确认的边界；不得发起注意、追视或唤醒 |
| 明确没有确认目标 | 不可以 | 服从外部状态；并不等同于传感器数据无效 |
| `data_valid` 为假 | 不可以 | 标记数据不可用，不能把它解释成确认目标或必然离开 |
| 坐标缺失、非数值或无穷大 | 不可以 | 按无效追视坐标处理 |
| 坐标为有限数值但越界 | 有条件 | 只有有效、已确认目标才使用裁剪后的坐标，并提供越界诊断 |
| 外部状态为 `sleeping` | 不可以启动追视 | 闭眼状态优先；候选和预览点击不能改变它 |
| `ui_visible` 为假 | 不继续推进角色动画 | 角色模型冻结，输出黑底；模拟输入时间仍可推进，恢复时重新取当前输入 |

即使输入包含有效确认目标，`IDLE` 仍按待机呈现，`LEAVE` 仍按离开呈现，`sleeping` 仍保持休眠；模型不擅自把外部状态改成 `TRACKING` 或 `waking`。

坐标无效的参考回退为：从第一帧无效追视输入起，短暂保留当时已经绘出的注视方向 **250 ms**，随后用 **450 ms** 的 smoothstep 过渡回到精确中心。它只处理画面连续性，不产生 `LEAVE`，不撤销或确认目标，也不触发休眠。主工程若已有明确的丢帧、保持或离开机制，应由其决定该回退是否采用及如何协调。

## 时间与确定性

参考模型只接受外部注入的绝对时间 `now_ms`，不在动作计算中读取 `Date.now()`、`performance.now()` 或随机数。预览播放器可以读取浏览器时钟，再将换算后的时间注入模型；这与模型自行读取真实时间是两件事。

`state_entered_ms` 是当前状态实际进入时间，和 `now_ms` 使用同一时间基准。状态动作的相位按 `now_ms - state_entered_ms` 求值，因此暂停或拖动预览不会被误当成新的状态进入。同一场景、同一主题和同一注入时间应得到相同的结果。

预览从场景起点以固定步长 `1000/60 ms` 重建到目标时间，固定种子为 `0x4d4f5341`。这样既能按任意顺序拖动时间轴，也能重复生成截图，而无需依赖上一次实际播放到哪里。固定步长是参考模型的确定性策略，不是设备刷新率承诺。

## 本包实现的参考参数

下表描述 `preview/model.js` 中的建议参数，**不规定主工程状态停留时间或迁移阈值**。例如，预览里 `NOTICE` 被脚本保留 900 ms，并不等于主工程必须在 900 ms 后切到 `TRACKING`。

| 动作 | 参考参数 | 含义 |
|---|---:|---|
| 普通追视平滑 | 时间常数 135 ms | 每步使用 `1-exp(-dt/135)` 接近当前目标；不是固定时长完成动画 |
| 保持状态平滑 | 时间常数 260 ms | 有效目标仍可更新，但关注动作更缓 |
| 待机平滑 | 时间常数 220 ms | 跟随轻微的确定性待机游移，不读取候选方向 |
| 注意动作 | 220 ms | 初始轻微收拢眼睑，闭合度从 0.12 回到睁开；不产生业务确认 |
| 无效追视输入回退 | 保持 250 ms，再归中 450 ms | 以第一帧无效时已经绘出的眼位为起点 |
| 离开归中 | 600 ms | 从进入 `LEAVE` 时的眼位平滑回中 |
| 离开时的轻眨 | 从状态进入后 280 ms 起 | 使用约 240 ms 的眨眼包络，最大闭合度 0.95 |
| 可见状态下进入休眠 | 700 ms | 平滑闭眼并回中；已经休眠时直接进入则立即闭眼 |
| 唤醒打开 | 650 ms | 眼睑打开，同时按当前有效确认目标渐进建立关注 |
| 常规眨眼周期 | 4,600 ms | 起点由固定种子在周期内确定；不是实时随机定时器 |
| 单次常规眨眼 | 闭合 75 ms、闭眼 35 ms、打开 130 ms | 合计 240 ms；固定种子有时产生一次较轻的第二次眨眼 |

待机游移很小：归一化水平振幅的理论上限约 0.11，垂直约 0.07；映射到夜枭约为水平 1.98 px、垂直 0.84 px，深海约为水平 2.20 px、垂直 0.84 px。它只表达静止角色的轻微活动，不响应候选坐标。

## 插值、打断与循环终止

有限时长过渡使用：`p = clamp((now_ms - state_entered_ms) / T, 0, 1)`，`s = p²·(3-2p)`，`value = start + (end-start)·s`。无效输入回退使用自己的失效起点与保持结束时间；不把它改写成业务状态进入时间。

追视使用指数平滑：`a = 1-exp(-dt/τ)`，`gaze = previous + a·(target-previous)`；普通追视和 `HOLD` 采用前述不同的时间常数。眼睑闭合量 `c∈[0,1]` 映射为 `z=8c`，取 `k=floor(z)` 与 `min(k+1,8)` 两级，权重为 `u=z-k`。预乘颜色和 Alpha 按 `(1-u)`、`u` 加权；最近级别替代则取 `round(z)`。这里规定的是参考数学结果，不要求原生渲染器提供 Canvas 的 `lighter` 操作。

当外部 `role_state` 或真实 `state_entered_ms` 改变，新状态立即取得动作控制权；旧动作不排队等待完成，也不通过完成回调再写回一个过期状态。追视会沿用当前可见眼位继续平滑；进入 `LEAVE` 或可见状态下进入 `sleeping` 时，以当时眼位作为过渡起点，入睡还保留当时眼睑闭合量。其他眼睑动作按新状态的当前相位求值，不声称任意不合理的状态跳转都会得到无缝混合。

同一状态中的坐标更新不重置状态进入时间。仅切主题也不重置业务相位。重新显示或直接向有状态 `step` 注入倒退时间时，模型按当前输入重新初始化，旧注意动作、眨眼和失效缓存都不会补播。预览时间轴的跳转则通过专用重放路径重建到目标时刻，以保持与从起点播放一致。

常规眨眼仅在待机、跟随和保持等允许的状态中由绝对相位求值；注意、离开、休眠、唤醒各自的眼睑动作接管后，常规眨眼不在后台排队。一次闭合/打开包络结束即返回当前状态的持续画面；`LEAVE` 归中完成后保持中心，`sleeping` 闭合完成后保持闭眼，`waking` 打开完成后保持睁眼及当前关注。它们 **不自动触发下一业务状态**，必须等待主工程的新输入。

角色隐藏时停止其循环推进；重新进入使用新可见时期的参考眨眼节奏。完整演示到 48 秒时播放器暂停，直接进入场景到 6 秒暂停；只有明确重播才从场景起点重新开始。上述终止规则属于参考播放器与动作模型，不设定主工程的 UI 停留时长。

## 进入、离开和重新进入

### 当前已有确认目标

在首次进入、主题切换或重新显示时，取当前有效坐标及外部状态。如果当前为 `TRACKING` 或 `HOLD`，直接建立相符的画面；如果外部确实给出尚在进行的 `NOTICE` 或 `waking`，按其真实进入时间呈现剩余相位。不得为了让动画显眼而伪造新的到达时间。

### 当前没有目标

取当前无目标信息及外部状态，呈现待机、离开或其他已给定状态。不要保留上一个主题或上一次显示期间的旧目标作为新的确认目标；也不要把“无目标”一律解释成新发生的离开动作。

### 当前正在休眠

以闭眼画面进入，维持外部 `sleeping`。未确认候选和界面重新显示都不能产生唤醒。只有外部状态明确进入 `waking`，才展示相应动作。

### 隐藏期间和恢复时

模拟角色隐藏后不再继续推进角色模型、排队眨眼或积累完成回调。参考模型在首次隐藏时进入暂停态，之后的隐藏样本不再更新模型状态；重新进入时重新初始化，丢弃旧动作和注视缓存。为展示外部状态在隐藏期间的变化，参考播放器仍可推进注入时间并更新画面外的面板，角色区域显示黑底。

真正的产品界面适配层应取消不再需要的角色帧订阅、回调和待执行动作，并按引擎规则处理临时缓冲与纹理。当前业务时间仍可由外部系统推进；本包不控制传感器或系统计时。HTML 工具在浏览器标签页隐藏或离开时暂停播放器，这与时间线中的模拟角色切出是两个不同层次；这项 HTML 行为尚未完成真实浏览器验收。

恢复时使用最新的 `now_ms`、`state_entered_ms`、角色状态和目标样本重建画面。隐藏期间曾发生但现在已经过期的 `NOTICE` 不补播。休眠进入仍闭眼；无目标进入不追踪旧坐标；确认目标进入按当前状态处理。

## 动作表达限制

眼球位移发生在固定前景后方；眼睑原地闭合，外部美术不随眨眼拉伸。三个主题使用一致的状态含义，机械眼仅采用较小的位移幅度。任何轻微待机动作都不能看起来像在追踪未确认的候选。

参考预览的播放、拖动、重播、变速和主题按钮都在画面之外。它们只是审阅工具，不作为角色点击反馈，也不代表最终全局手势接入。画面中不得显示目标种类、距离或探测置信度。

## 动态评审应覆盖的内容

完整评审应包含待机、未确认候选、确认到达、左右上下追视、保持、离开、待机到休眠、休眠中的候选、确认后的唤醒，以及动作中途切走后分别以确认目标、无目标和休眠重新进入。坐标无效与恢复也需要单独覆盖。

拖动到某一时间的静态画面可检查外观；连续参考视频可检查节奏、恢复和动作衔接；参考模型检查可验证边界条件。随包视频和截图由共享渲染器在离屏 Canvas 中生成，HTML 控件尚未经真实浏览器验收。它们各自证明的范围不同。原生帧耗时、输入事件顺序和硬件显示质量必须另行验证。

## 预览场景与时间线

`full` 是 **48 秒的模拟完整演示**；`enter_target`、`enter_empty`、`enter_asleep` 各为 **6 秒的直接进入场景**。三个主题共用同一输入时间线。时间区间采用左闭右开，最后一帧除外。

| 完整演示时刻或区间 | 注入内容与检查目的 |
|---|---|
| 0–6 s | 待机；3–5 s 只出现未确认候选，画面仍沿同一待机轨迹 |
| 6–6.9 s | `NOTICE` 与有效确认目标同时由脚本注入 |
| 6.9–12.5 s | `TRACKING`，覆盖左、右、下、上四个方向 |
| 12.5–15.5 s | 先 `HOLD`，14.4 s 起 `LEAVE`，15.5 s 回待机 |
| 19–22.4 s | `sleeping`；20.4–21.6 s 的候选不唤醒 |
| 22.4–26.7 s | 先 `waking`，23.2 s 起继续跟随 |
| 26.7–28.4 s | 注意动作开始后于 27 s 隐藏；28.4 s 按当前 `TRACKING` 和目标重入 |
| 30.6–31.6 s | `data_valid=false`；状态仍为 `TRACKING`，先保持再归中，之后恢复 |
| 32.6–34.2 s | 另一次注意动作后于 32.9 s 隐藏；34.2 s 按当前无目标 `IDLE` 重入 |
| 36.6–38.2 s | 隐藏期间外部于 36.8 s 进入休眠；38.2 s 重入时直接闭眼 |
| 39–41.2 s | 39–40 s 的睡眠候选被忽略；40.4 s 注入 `waking` 与确认目标 |
| 42.5–43.25 s | 坐标 `target_y=NaN`，单独演示无效坐标回退与恢复 |
| 44.2–48 s | 保持，45.5 s 离开，46.4 s 待机直至结束 |

直接进入场景分别检查：已有目标时直接进入 `TRACKING`，无目标时进入 `IDLE`，已休眠时直接闭眼。它们不先播放一段待机或注意来掩盖初始化错误。场景详细取样以 `preview/timeline.js` 为准；此表是预览安排，不是主工程业务规则。
