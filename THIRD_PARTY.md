## Recreate the dependency layout elsewhere

The review ZIP is intentionally not a vendor bundle. Place `mosaico-peek` next to the official `esp-mosaico-vibe` workspace, checked out at the exact revision in `dependencies.json`, with its `esp-mosaico-bsp` and `esp-mosaico-utils` submodules initialized to those pins (and ESP-Iris initialized inside utils). Use the existing SDK revision and GSP versions, or install these exact tool versions in that separate environment. Do not switch a shared checkout to another revision just to satisfy this app.

Run `python3 tools/bootstrap.py`. It verifies the local Vibe/BSP/utils revisions. If the existing `../Mondrian/components/mosaico_module_thermal` is available it verifies/copies only the allowlisted driver files into ignored `deps/`. Otherwise it downloads the driver from the official immutable BSP commit and verifies its SHA-256 allowlist. An official BSP checkout can also be supplied with `PEEK_THERMAL_SOURCE=/path/to/bsp/components/mosaico_module_thermal`. It never writes to those source directories. An offline environment must supply that driver source and the pinned components/tool archives locally.

The dependency lock was seeded from the already validated Mondrian app, then re-resolved for this app. Registry component versions stayed identical; local source paths were relocated. `lvgl==9.5.0` preserves compatibility with the fixed BSP display adapter. No shared environment was upgraded.
