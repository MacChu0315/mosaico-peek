## Recreate the dependency layout elsewhere

The review ZIP is intentionally not a vendor bundle. Place `mosaico-peek` next to an independent official `esp-mosaico-vibe-iris02` workspace, checked out at the exact revision in `dependencies.json`, with its `esp-mosaico-bsp` and `esp-mosaico-utils` submodules initialized to those pins (and ESP-Iris initialized inside utils). Use the existing SDK revision and GSP versions, or install these exact tool versions in that separate environment. Do not switch a shared checkout to another revision just to satisfy this app.

Run `python3 tools/bootstrap.py`. It verifies the local Vibe/BSP/utils revisions. It verifies/copies only the allowlisted thermal files from the pinned BSP into ignored `deps/`. Otherwise it downloads the driver from the official immutable BSP commit and verifies its SHA-256 allowlist. An official BSP checkout can also be supplied with `PEEK_THERMAL_SOURCE=/path/to/bsp/components/mosaico_module_thermal`. It never writes to those source directories. An offline environment must supply that driver source and the pinned components/tool archives locally.

The dependency lock was seeded from the already validated Mondrian app, then re-resolved for this app. The original registry set was retained except the new BSP-required official BMI270/BMM150 drivers; libpng1.6.58~2 and zlib1.3.2~1 are explicitly preserved. Local source paths are relocated. `lvgl==9.5.0` preserves compatibility with the fixed BSP display adapter. No shared environment was upgraded.
